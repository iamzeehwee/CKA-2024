## Task 10/40


In this exercise, you will explore namespaces in depth by creating multiple Kubernetes resources.

> [!NOTE]
> If you do not already have a Kubernetes cluster, you can create a local Kubernetes cluster by following [Day06 Video](https://youtu.be/RORhczcOrWs)
Also, could you do the port binding at the cluster level if you are using KIND? The Day9 video has the details on how to do that.

### Task details
- Create two namespaces and name them ns1 and ns2
  1. Create namespaces: kubectl create namespace ns1, kubectl create namespace ns2
  2. Verify the namespaces are created via the command: kubectl get ns
    NAME                 STATUS   AGE
    default              Active   15h
    kube-node-lease      Active   15h
    kube-public          Active   15h

    local-path-storage   Active   15h
    ns1                  Active   22s
    ns2                  Active   18s

- Create a deployment with a single replica in each of these namespaces with the image as nginx and name as deploy-ns1 and deploy-ns2, respectively
  1. Create deployment manifests for each namespace: deploy-ns1.yaml, deploy-ns2.yaml
  2. Create the deployment: kubectl create -f deploy-ns1.yaml -n ns1, kubectl create -f deploy-ns1.yaml -n ns2
  3. Verify the deployment is created in ns1: kubectl get all -n ns1

- exec into each pod and try to curl the IP address of the service running on the other namespace.
  1. Exec into a pod in ns2 to do the curl to svc-ns1 (10.96.122.67): kubectl exec -it deploy-ns2-d945d5f55-d8m2s -n ns2 -- sh
    # curl 10.96.122.67
    curl: (7) Failed to connect to 10.96.122.67 port 80 after 2 ms: Could not connect to server
    # curl 10.96.122.67:80
    curl: (7) Failed to connect to 10.96.122.67 port 80 after 1 ms: Could not connect to server
    # curl 10.96.56.224
    curl: (7) Failed to connect to 10.96.56.224 port 80 after 27 ms: Could not connect to server
    # curl 10.96.56.224:80
    curl: (7) Failed to connect to 10.96.56.224 port 80 after 4 ms: Could not connect to server

- This curl should work.
  1. No, it does not work. It is unable to access svc-ns1 and svc-ns2 via IP address but it is able to access pods in both ns1 and ns2.

- Now try curling the service name instead of IP. You will notice that you are getting an error and cannot resolve the host.
  1. Exec into a pod in ns2 to do curl via svc-ns1: kubectl exec -it deploy-ns2-d945d5f55-d8m2s -n ns2 -- sh
    # curl svc-ns1
    curl: (6) Could not resolve host: svc-ns1

- Now use the FQDN of the service and try to curl again, this should work.
  1. Exec into a pod in ns2, and find the /etc/resolv.conf file. This file is responsible for IP address to DNS resolution internally.
    $ kubectl exec -it deploy-ns2-d945d5f55-d8m2s -n ns2 -- sh
    # cat /etc/resolv.conf
    search ns2.svc.cluster.local svc.cluster.local cluster.local
    nameserver 10.96.0.10
    options ndots:5

- In the end, delete both the namespaces, which should delete the services and deployments underneath them.
